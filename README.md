# West Dev Flappy Bird

## Overview

**WEST DEV — FLAPPY BIRD** is a pixel-art arcade competition for West Dev club events.
Players walk up to one laptop, enter their Telegram username, get **3 attempts**, and try to
beat the leaderboard.

There is **no backend**: no server, API or database. Everything runs in the browser, and all
players and scores are saved in that browser's `localStorage` on the event laptop.

## Features

- **Telegram login.** Input is normalized (`  @Shakhzod ` → `@shakhzod`) and validated. One username = one player.
- **3 attempts per player.** An attempt is used when the run **starts**, so refreshing the page never gives it back.
- **Best score only.** The leaderboard ranks each player by their best result.
- **Leaderboard.** Live TOP 10 with medals, a 👑 current champion banner, a global rank for every player,
  and animations for new rows, score bounces and position changes.
- **Search.** Finds any player on the laptop, case-insensitive (`alex`, `@ALEX`), debounced, with partial matches.
- **Game Over screens.** Score count-up, ★ NEW HIGH SCORE ★, "YOU MADE THE TOP 10!", a full-screen
  👑 NEW CHAMPION! celebration, and a FINAL RESULT screen after the 3rd attempt.
- **Pixel art.** Original pixel font, sprites, parallax background and particles, all generated in code.
- **Sound.** Original arcade sound effects synthesized with the Web Audio API. On/off setting is saved.
- **Fullscreen.** The game requests fullscreen on START GAME and keeps working if the browser refuses.
- **Responsive.** Works on laptop, desktop, tablet and phone. Supports keyboard, mouse and touch.
- **Admin panel (hidden).** Export / import JSON backups, delete one player (typos), reset all data
  (with confirmation and UNDO), and an FPS meter.
- **Resilient storage.** Damaged data is repaired or shows a recovery screen instead of a white page.
- **Works offline.** No CDN, no external fonts, no network requests at runtime.

## Architecture

Plain HTML/CSS/JavaScript. There is no build step and nothing to install.
The scripts are classic `<script>` files that share one `window.WD` namespace, so the game also
runs by **double-clicking `index.html`**. ES modules would not allow that.

```
index.html
css/
  font.css                  pixel font embedded as data: URI (generated; works over file://)
  reset.css  variables.css  global.css  menu.css  leaderboard.css  game.css
js/
  config.js                 GAME_CONFIG, UI_CONFIG, palette, storage keys (all tunables)
  main.js                   entry point
  app/App.js                flow controller: menu -> start -> play -> game over -> menu
  game/
    Game.js                 state machine + update/render orchestration
    GameLoop.js             requestAnimationFrame, fixed timestep, interpolation
    Bird.js  Pipe.js  Collision.js  ParticleSystem.js  Background.js  Input.js
  storage/
    Storage.js              SafeStore, versioned schema, migrations, GameStorage
    PlayerStorage.js        getPlayer / createPlayer / useAttempt / updateBestScore
    LeaderboardStorage.js   getTopPlayers / getRank / getChampion / searchPlayers
    SettingsStorage.js      sound, current player, intro flag
    BackupService.js        export / import JSON
  ui/
    StartScreen.js  Leaderboard.js  Search.js  Hud.js  GameOver.js  Celebration.js
    AdminPanel.js  ErrorScreen.js  Intro.js  Dialog.js  Toast.js  Fullscreen.js  widgets.js
  utils/  username.js  ranking.js  dom.js
  gfx/sprites.js            pixel-art maps (bird, icons) rendered to canvases
  audio/SoundManager.js     Web Audio sound effects
assets/
  fonts/west-pixel.ttf      original pixel font (generated by tools/build-font.mjs)
  sprites/favicon.svg
tools/
  build-font.mjs            regenerates the font (node tools/build-font.mjs)
  serve.py                  no-cache local server for development
```

Some design rules:

- The game engine (`js/game`) knows nothing about storage or menus. It reports through callbacks.
- Only `js/storage/Storage.js` touches `localStorage`. Everything else goes through the repositories.
- Usernames are always written with `textContent`, never `innerHTML`.

## Local Storage

| Key                         | Purpose                                                     |
| --------------------------- | ----------------------------------------------------------- |
| `westdev.flappy.data`       | main database (schema below)                                |
| `westdev.flappy.backup`     | rolling copy of the last good save, used for recovery       |
| `westdev.flappy.undo`       | snapshot taken right before the last reset or import        |
| `westdev.flappy.corrupted`  | an unreadable payload is kept here for manual inspection    |

```js
{
  version: 1,
  players: {
    "@alex": {
      username: "@alex",
      bestScore: 124,
      bestScoreAt: 1720000000000, // when this best was first reached (tie-break)
      attemptsUsed: 3,            // always 0..3
      scores: [20, 124, 31],      // last results
      createdAt: 1720000000000,
      updatedAt: 1720000000000
    }
  },
  settings: { soundEnabled: true },
  session:  { currentUsername: "@alex" }
}
```

- **Versioning.** `version` plus a migration table in `Storage.js` lets the format change later without losing data.
- **Validation.** Every write is applied to a copy, validated (attempts clamped to 0..3, scores ≥ 0,
  usernames re-checked) and only then saved.
- **Ranking.** `bestScore DESC`, then `bestScoreAt ASC`, so whoever reached a score first ranks higher.
  A player appears in the ranking after finishing their first game.
- **Corruption.** If the data can't be parsed, the game shows **CORRUPTED GAME DATA** with
  **RESTORE BACKUP / IMPORT FILE / RESET GAME** instead of a white screen.

## Game Mechanics

All values live in `GAME_CONFIG` in `js/config.js`, so balancing is a one-file change.

- The world is 320 virtual pixels high and as wide as the screen's aspect ratio. It is rendered
  at low resolution and scaled up with `image-rendering: pixelated`.
- Physics run on a fixed 120 Hz timestep with render interpolation. The game feels the same at
  60, 120 or 144 FPS, and a stalled tab can't teleport the bird.
- Gravity, flap impulse, max fall speed, and bird rotation (up on flap, nose-dive when falling).
  The wings flap in 3 frames.
- Random pipe gaps, limited in how far they move between pipes. Pipes are spaced by distance,
  so the spacing doesn't depend on FPS.
- Difficulty ramps up slowly: pipe speed rises and gaps shrink with score, both capped.
- Collision uses a circle for the bird against rectangles for pipe bodies and caps, plus ground and ceiling.
- +1 for each pipe pair passed.
- On a crash: white flash, screen shake, particles, hit sound, the bird falls, then the Game Over panel appears.
- Game Over buttons ignore input for 0.9 s, so a player mashing SPACE can't burn an attempt by accident.

## Controls

| Action            | Desktop                     | Touch      |
| ----------------- | --------------------------- | ---------- |
| Flap              | `SPACE`, `↑`, `W`, left click | tap        |
| Start (profile)   | `ENTER` or START GAME       | tap button |
| Play again        | `ENTER` or PLAY AGAIN       | tap button |
| Admin panel       | `Ctrl + Shift + A`          | tap the **WD** logo 5× quickly |

Holding a key flaps once; you have to press again for the next flap.
Add `?fps` to the URL to show the FPS meter.

## Data Backup

**Before the event**, and from time to time during it:

1. Open the admin panel (`Ctrl + Shift + A`).
2. **EXPORT DATA** downloads `west-dev-flappy-backup.json`.
3. **IMPORT DATA** restores a backup file. It replaces the current players; the previous data
   can be brought back with **UNDO LAST RESET / IMPORT**.
4. **RESET ALL DATA** asks *ARE YOU SURE?* before deleting all players. Undo is available afterwards.
5. **DELETE ONE PLAYER** removes a typo like `@alexx`.

> ⚠️ Data belongs to **one browser on one laptop**. Clearing site data, using a private window, or
> switching browsers starts an empty leaderboard. Export a backup first.

## Running Locally

Any of these work. No installation is needed:

- **Double-click `index.html`.** It works from `file://`.
- `python tools/serve.py` → <http://localhost:5173> (no caching, useful while editing)
- `npx serve .` or any other static server

To regenerate the pixel font after editing glyphs, run `node tools/build-font.mjs`. It writes both
`assets/fonts/west-pixel.ttf` and the embedded `css/font.css`.

**Event checklist:** open the game once with internet or locally → enter fullscreen →
check that sound works → export an empty or test backup → reset → go.

## Deployment

It's a static site, so you can upload the folder as it is:

- **Netlify / Vercel:** drag and drop the folder, or connect the repo with no build command and `/` as the publish directory.
- **GitHub Pages:** push and enable Pages for the branch root.

All paths are relative, so it also works from a sub-path like `user.github.io/west-dev-flappy/`.
After the first load everything is local, so the game keeps working if the venue's Wi-Fi drops.
Scores always stay in the laptop's browser, even when the site is hosted online.
